solver
=============
(English below)

Popis
----
Zdrojový soubor: solver.c

Tento modul poskytuje high-level rozhraní pro řešení závislostí balíčků pomocí libsolv.
Zahrnuje vytvoření solveru s nastavením flags (Conda/LFS kompatibilita), rekurzivní zpracování
build-time závislostí (mkdeps) s ochranou proti cyklům, řešení runtime závislostí,
vytváření a ordering transakcí, a zobrazování řešení problémů (proof).
Integruje se s parser.c (get_custom_mkdeps) a utils/print.c (display_transaction).

Klíčové funkce
----
Solver *create_solver(Pool *pool);
- Vytvoří nový Solver pro daný Pool pomocí solver_create; nastaví flags (ALLOW_UNINSTALL=1, ALLOW_VENDORCHANGE=1, 
  ALLOW_DOWNGRADE=0, NO_AUTOTARGET=1) pro explicitní job control a flexibilní řešení konfliktů;
  volá set_system_arch(pool) pro detekci architektury (z system_helpers.c); vytvoří whatprovides index 
  (pool_createwhatprovides); loguje úspěch; vrací Solver* nebo NULL při chybě.

void add_mkdeps_to_queue(Queue *job, Id p, Pool *pool, Repo *repo, int depth);
- Rekurzivně přidává build-time závislosti (mkdeps) do job queue pro daný Solvable Id p;
  načte mkdeps z Repodata pomocí get_custom_mkdeps (z parser.c), parsuje JSON array, pro každý mkdep:
  vytvoří Id (pool_str2id), přidá do job jako SOLVER_INSTALL | SOLVER_SOLVABLE_NAME (queue_push2),
  najde odpovídající Solvable v Repo (FOR_REPO_SOLVABLES s match name Id), rekurzivně volá sebe pro nalezený Solvable;
  obsahuje depth limit (MAX_RECURSION_DEPTH=10 z common.h) proti cyklickým závislostem; loguje každý mkdep a depth;
  cleanup: json_decref(mkdeps); používá se v solve_dependencies před přidáním runtime deps.

Queue *solve_dependencies(Solver *solv, const char *pkg_name, Pool *pool, Repo *repo);
- Hlavní entry point pro řešení závislostí: Najde Solvable pro pkg_name (pool_str2id, FOR_REPO_SOLVABLES),
  inicializuje job Queue (queue_init), rekurzivně přidá mkdeps (add_mkdeps_to_queue, depth=0),
  přidá hlavní package jako SOLVER_INSTALL | SOLVER_SOLVABLE (používá Id solvable main_p místo name_id), spustí solver (solver_solve),
  pokud problém: zobrazí proof (display_problem_proof) a v non-test módu ptá se uživatele (user_confirm),
  vytvoří transakci (solver_create_transaction), seřadí (transaction_order), získá installed result
  (transaction_installedresult), zobrazí transakci (display_transaction z utils/print.c), cleanup (transaction_free, queue_free);
  vrací Queue* s installed result (caller musí queue_free + solv_free) nebo NULL při chybě/prázdném výsledku.

void display_problem_proof(Solver *solv, int problem);
- Zobrazí důkaz (proof) pro daný problém číslo problem; adaptace z solv.c (doshowproof);
  inicializuje Queue lq, načte learnt rules (solver_get_learnt s SOLVER_DECISIONLIST_PROBLEM),
  pro každý learnt rule: vypíše "Learnt rule #N" a volá internal_display_proof s SOLVER_DECISIONLIST_LEARNTRULE,
  pak vypíše "Proof:" a volá internal_display_proof s SOLVER_DECISIONLIST_PROBLEM, cleanup (queue_free);
  používá se v solve_dependencies při solver_solve failure.

static void internal_display_proof(Solver *solv, Id id, int flags, Queue *lq);
- Interní helper pro display_problem_proof; adaptace z solv.c (showproof);
  načte decision list (solver_get_decisionlist s flags | SORTED | WITHINFO | MERGEDINFO),
  iteruje přes decisions (8 elementů per decision: v, reason, bits, type, from, to, dep),
  skipuje "obvious" decisions (SOLVER_RULE_PKG_SAME_NAME), získá solvables (solver_decisionlist_solvables),
  formátuje output: "unsolvable" pro SOLVER_REASON_UNSOLVABLE, "conflicted/installed <packages>" pro ostatní,
  používá solver_reason2str, solver_decisioninfo2str, pool_solvidset2str; zobrazí learnt rule reference pokud v lq;
  cleanup (queue_free).

Integrace v projektu
----
Používá se v main.c: po načtení pool/repo z parser.c (load_repository), volá se solve_dependencies(solv, "pkg-name", pool, repo),
výsledek (Queue*) se předává builderu pro instalaci balíčků. Separace mkdeps (build-time) a runtime deps zajišťuje korektní
build ordering (mkdeps first, pak runtime). Testováno v test_solver.c (Check framework) s mock repo; ~70% coverage včetně
rekurze, циклů, konfliktů.

solver
=============

Description
----
Source file: solver.c

This module provides a high-level interface for solving package dependencies using libsolv.
Includes solver creation with flags (Conda/LFS compatibility), recursive processing of
build-time dependencies (mkdeps) with cycle protection, runtime dependency resolution,
transaction creation and ordering, and problem proof display.
Integrates with parser.c (get_custom_mkdeps) and utils/print.c (display_transaction).

Key functions
----
Solver *create_solver(Pool *pool);
- Creates new Solver for given Pool using solver_create; sets flags (ALLOW_UNINSTALL=1, ALLOW_VENDORCHANGE=1,
  ALLOW_DOWNGRADE=0, NO_AUTOTARGET=1) for explicit job control and flexible conflict resolution;
  calls set_system_arch(pool) for architecture detection (from system_helpers.c); creates whatprovides index
  (pool_createwhatprovides); logs success; returns Solver* or NULL on error.

void add_mkdeps_to_queue(Queue *job, Id p, Pool *pool, Repo *repo, int depth);
- Recursively adds build-time dependencies (mkdeps) to job queue for given Solvable Id p;
  loads mkdeps from Repodata using get_custom_mkdeps (from parser.c), parses JSON array, for each mkdep:
  creates Id (pool_str2id), adds to job as SOLVER_INSTALL | SOLVER_SOLVABLE_NAME (queue_push2),
  finds matching Solvable in Repo (FOR_REPO_SOLVABLES with name Id match), recursively calls itself for found Solvable;
  includes depth limit (MAX_RECURSION_DEPTH=10 from common.h) against circular dependencies; logs each mkdep and depth;
  cleanup: json_decref(mkdeps); used in solve_dependencies before adding runtime deps.

Queue *solve_dependencies(Solver *solv, const char *pkg_name, Pool *pool, Repo *repo);
- Main entry point for dependency resolution: Finds Solvable for pkg_name (pool_str2id, FOR_REPO_SOLVABLES),
  initializes job Queue (queue_init), recursively adds mkdeps (add_mkdeps_to_queue, depth=0),
  adds main package as SOLVER_INSTALL | SOLVER_SOLVABLE_NAME, runs solver (solver_solve),
  if problems: displays proof (display_problem_proof) and in non-test mode asks user (user_confirm),
  creates transaction (solver_create_transaction), orders it (transaction_order), gets installed result
  (transaction_installedresult), displays transaction (display_transaction from utils/print.c), cleanup (transaction_free, queue_free);
  returns Queue* with installed result (caller must queue_free + solv_free) or NULL on error/empty result.

void display_problem_proof(Solver *solv, int problem);
- Displays proof for given problem number; adapted from solv.c (doshowproof);
  initializes Queue lq, loads learnt rules (solver_get_learnt with SOLVER_DECISIONLIST_PROBLEM),
  for each learnt rule: prints "Learnt rule #N" and calls internal_display_proof with SOLVER_DECISIONLIST_LEARNTRULE,
  then prints "Proof:" and calls internal_display_proof with SOLVER_DECISIONLIST_PROBLEM, cleanup (queue_free);
  used in solve_dependencies on solver_solve failure.

static void internal_display_proof(Solver *solv, Id id, int flags, Queue *lq);
- Internal helper for display_problem_proof; adapted from solv.c (showproof);
  loads decision list (solver_get_decisionlist with flags | SORTED | WITHINFO | MERGEDINFO),
  iterates over decisions (8 elements per decision: v, reason, bits, type, from, to, dep),
  skips "obvious" decisions (SOLVER_RULE_PKG_SAME_NAME), gets solvables (solver_decisionlist_solvables),
  formats output: "unsolvable" for SOLVER_REASON_UNSOLVABLE, "conflicted/installed <packages>" for others,
  uses solver_reason2str, solver_decisioninfo2str, pool_solvidset2str; shows learnt rule reference if in lq;
  cleanup (queue_free).

Project integration
----
Used in main.c: after loading pool/repo from parser.c (load_repository), calls solve_dependencies(solv, "pkg-name", pool, repo),
result (Queue*) is passed to builder for package installation. Separation of mkdeps (build-time) and runtime deps ensures correct
build ordering (mkdeps first, then runtime). Tested in test_solver.c (Check framework) with mock repo; ~70% coverage including
recursion, cycles, conflicts.
