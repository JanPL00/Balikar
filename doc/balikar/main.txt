main
=============
(English below)

Popis
----
Zdrojový soubor: main.c

Tento modul představuje hlavní entry point aplikace Balikar Package Manager.
Poskytuje CLI rozhraní, parsování argumentů, orchestraci celého workflow (parse → solve → download → build → install),
a řídí životní cyklus libsolv struktur (Pool, Repo, Solver, Transaction).
Podporuje různé příkazy (install, build, resolve, repos, repo-update) s možnostmi jako debug režim, dry-run, staging kontrola.
Integruje všechny moduly (parser, solver, downloader, builder) do koherentního workflow.

Klíčové struktury
----
typedef struct {
    int debug_level;      // Úroveň debug výpisů (0=off, 1=info, 2=detailed)
    int dry_run;          // Simulační režim bez skutečných změn
    int no_staging;       // Vypnutí staging režimu (instalace přímo)
    char *staging_dir;    // Cesta k staging adresáři (výchozí: /tmp/balikar_staging)
    char *root_path;      // Cesta k target root pro instalaci (výchozí: /)
    char *build_tmp_dir;  // Dočasný adresář pro buildy (výchozí: /tmp)
    char *repo_path;      // Cesta k repozitáři (výchozí z repos.conf)
    char *local_package;  // Cesta k lokálnímu tar.xz/tar.gz/tar.bz2 mimo repo
    const char *command;  // Příkaz k provedení (install, build, resolve, remove, repos, repo-update, download)
    const char *package_name; // Název balíčku pro operaci
} cli_config_t;
- Struktura pro konfiguraci z CLI argumentů; inicializována v parse_args, použita v main workflow.

Klíčové funkce
----
static void parse_args(int argc, char **argv, cli_config_t *cfg);
- Parsuje CLI argumenty pomocí getopt_long; podporované long options: --help, --debug, --dry-run, --no-staging, --no-deps,
  --staging-dir, --root, --build-tmp-dir, --repo, --local-package, --output-dir; krátké: -h, -d (debug lze opakovat);
  zpracovává command (první pozitional arg) a package_name (druhý pozitional arg); nastavuje výchozí repo_path z repos.conf;
  volá print_usage při chybě nebo -h.

int main(int argc, char **argv);
- Hlavní entry point:
  1. Inicializuje cli_config_t (parse_args)
  2. Aplikuje konfiguraci (set_staging_dir, set_staging_enabled, set_build_tmp_dir z system_helpers)
  3. Vytváří Pool (pool_create)
  4. Načítá repository (load_repository z parser.c)
  5. Rozhoduje podle příkazu:
     - install/build: Vytvoří solver, solve dependencies (solve_dependencies), vytvoří transakci (solver_create_transaction),
       zobrazí plán (display_transaction), user_confirm pokud není dry-run, iteruje přes transakční kroky,
       stahuje balíčky (download_package), stahuje extras (download_extras), builduje (commit_element z builder.c),
       instaluje (install_package z installer.c) pokud je příkaz install
     - remove: Odinstaluje balíček voláním erase_package z installer.c
     - resolve: Pouze solve + zobrazí transakci bez download/build
     - repos: Zobrazí název repo a počet balíčků (repo->nsolvables)
     - repo-update: Uvolní repo/pool, znovu vytvoří pool, volá generate_repodata, znovu načte repository, zobrazí počet balíčků
  6. Cleanup: repo_free, pool_free, free(cfg pointers)
  7. Vrací exit_code (0=úspěch, ERR_SOLVE_FAIL, ERR_DOWNLOAD_FAIL, ERR_BUILD_FAIL)

Podporované příkazy
----
install <pkg>
- Plný workflow: dependency resolution → download → build → install do staging → merge do target root
- Podporuje --local-package pro instalaci lokálního tar archivu
- Podporuje --root pro instalaci do custom chroot (výchozí: /)
- Použití: balikar install glibc
          balikar install --root=/mnt/lfs gzip
          balikar install --local-package=/path/to/pkg.tar.xz --root=/tmp/test

build <pkg>
- Podobné install, ale POUZE build do staging (bez merge do root)
- Výsledek zůstane v --staging-dir pro manuální kontrolu
- Použití: balikar build hello
          balikar build --staging-dir=/tmp/my_staging gzip

resolve <pkg>
- Pouze dependency resolution (dry-run solver); zobrazí transakční plán bez provedení změn
- Použití: balikar resolve gcc

repos
- Zobrazí načtené repozitáře a počet balíčků
- Použití: balikar repos

repo-update
- Regeneruje repodata.json z aktuální struktury repozitáře; uvolní pool/repo, zavolá generate_repodata,
  znovu načte repository a zobrazí statistiky
- Použití: balikar repo-update

download <pkg>
- Stahuje zdrojové soubory balíčku bez buildu; podporuje --output-dir pro vlastní cílovou cestu
  nebo použije lokální repository z repos.conf; s --no-deps stáhne pouze balíček bez závislostí
- Použití: balikar download bash
          balikar download --output-dir=/tmp/sources glibc
          balikar download --no-deps --output-dir=/custom/path gcc

remove <pkg>
- Odinstaluje balíček ze systému; odstraní všechny soubory a aktualizuje databázi
- Podporuje --root pro odinstalaci z custom chroot
- Použití: balikar remove gzip
          balikar remove --root=/mnt/lfs bash

Globální options
----
-h, --help
- Zobrazí help message (print_usage) a ukončí program s exit_code 0

-d, --debug
- Zvyšuje debug_level (lze opakovat: -d -d pro level 2); aplikováno globálně přes common.h logging

--dry-run
- Simulační režim: zobrazí plán, přeskočí download a build; užitečné pro preview změn

--no-staging
- Vypne staging režim (set_staging_enabled(0)); instalace proběhne přímo bez DESTDIR=$P mezikroku

--staging-dir=PATH
- Nastaví vlastní staging adresář (výchozí: /tmp/balikar_staging); volá set_staging_dir(PATH)
- Staging je dočasné místo pro DESTDIR během buildu
- Po úspěšné instalaci se automaticky vyčistí

--root=PATH
- Nastaví cílový root pro instalaci (výchozí: /)
- Používá se pro LFS/chroot buildy nebo testovací prostředí
- Databáze balíčků uložena v {root}/var/lib/balikar/installed.json
- Použití: --root=/mnt/lfs nebo --root=/tmp/test_root

--build-tmp-dir=PATH
- Nastaví dočasný adresář pro buildy (volá set_build_tmp_dir); výchozí: /tmp

--repo=PATH
- Nastaví cestu k repozitáři (výchozí: ./repo); použito v load_repository

--local-package=PATH
- Cesta k lokálnímu tar archivu (.tar.xz, .tar.gz, .tar.bz2) mimo repository
- Stáhne .build script z repository podle jména balíčku
- Provede stejný build workflow jako repository balíčky
- Použití: --local-package=/path/to/gzip-1.14.tar.xz

--output-dir=PATH
- Cílový adresář pro download command; stáhne balíčky do specifikovaného adresáře
  ve struktuře <letter>/<name>/<name>-<version>/; pokud není uvedeno, použije se první
  lokální repository z repos.conf

--no-deps
- Pro download command: stáhne pouze požadovaný balíček bez závislostí

Workflow install/build
----
1. Vytvoření Solver (create_solver z solver.c)
2. Dependency resolution (solve_dependencies z solver.c):
   - Najde hlavní balíček, rekurzivně přidá mkdeps, vytvoří job Queue, spustí solver
3. Vytvoření Transaction (solver_create_transaction z libsolv):
   - Převede solver output do transakce s kroky (INSTALL, UPDATE, etc.)
4. Zobrazení plánu (display_transaction z builder.c):
   - Vypíše seznam balíčků k instalaci/buildu
5. User konfirmace (user_confirm z cli_helpers.c):
   - Pokud není --dry-run, ptá se uživatele na potvrzení
6. Seřazení transakcí (transaction_order):
   - Seřadí kroky podle závislostí (leaf-first pro správné pořadí buildu)
7. Iterace přes kroky:
   - Pro každý INSTALL/MULTIINSTALL:
     a) Získá download_url (get_custom_source z parser.c)
     b) Stáhne balíček (download_package z downloader.c) - vrací FILE* s obsahem
     c) Stáhne extras (download_extras) - patche/skripty
     d) Builduje (commit_element z builder.c) - extrakce, aplikace patches, spuštění .build
8. Cleanup (transaction_free, queue_free, solver_free)

Workflow resolve
----
- Stejné kroky 1-4 jako install/build, ale přeskočí kroky 5-7 (žádný download/build)
- Užitečné pro kontrolu závislostí bez změn systému

Workflow repos
----
- Jednoduchý informační výpis: zobrazí repo_path a repo->nsolvables (počet načtených balíčků)

Workflow repo-update
----
1. Uvolnění současného repo a pool (repo_free, pool_free)
2. Vytvoření nového pool (pool_create)
3. Volání generate_repodata (z parser.c):
   - Prochází adresářovou strukturu repo/
   - Načítá index.json, zpracovává tar.bz2 archivy
   - Počítá SHA256 hashe, vytváří repodata.json
4. Opětovné načtení repository (load_repository)
5. Zobrazení statistik (počet balíčků)

Error handling
----
- Každá kritická operace kontroluje return hodnoty
- Error states: ERR_SOLVE_FAIL (dependency fail), ERR_DOWNLOAD_FAIL (download fail), ERR_BUILD_FAIL (build fail)
- Goto cleanup pattern pro správné uvolnění prostředků (repo, pool, malloc'd strings)
- Pokud pool/repo vytvoření selže, okamžitý return 1
- V případě chyby v transakci: break z loop, nastavení exit_code, goto cleanup

- Používá cli_helpers.c (print_usage, user_confirm)
- Používá common.h (log_*, error konstanty)

Description
----
Source file: main.c

This module represents the main entry point of the Balikar Package Manager application.
It provides a CLI interface, argument parsing, orchestration of the entire workflow (parse → solve → download → build → install),
and manages the lifecycle of libsolv structures (Pool, Repo, Solver, Transaction).
Supports various commands (install, build, resolve, repos, repo-update) with options like debug mode, dry-run, staging control.
Integrates all modules (parser, solver, downloader, builder) into a coherent workflow.

Key structures
----
typedef struct {
    int debug_level;      // Debug verbosity level (0=off, 1=info, 2=detailed)
    int dry_run;          // Simulation mode without actual changes
    int no_staging;       // Disable staging mode (install directly)
    char *staging_dir;    // Path to staging directory (default: $P from system_helpers)
    char *chroot_path;    // Path to chroot environment (default: /tmp/pm-chroot)
    char *build_tmp_dir;  // Temporary directory for builds (default: /tmp)
    char *repo_path;      // Path to repository (default: ./repo)
    char *local_package;  // Path to local tar.bz2 outside repo (TODO)
    const char *command;  // Command to execute (install, build, resolve, repos, repo-update)
    const char *package_name; // Package name for operation
} cli_config_t;
- Structure for CLI argument configuration; initialized in parse_args, used in main workflow.

Key functions
----
static void parse_args(int argc, char **argv, cli_config_t *cfg);
- Parses CLI arguments using getopt_long; supported long options: --help, --debug, --dry-run, --no-staging,
  --staging-dir, --chroot-path, --build-tmp-dir, --repo, --local-package; short: -h, -d (debug can be repeated);
  processes command (first positional arg) and package_name (second positional arg); sets default repo_path="./repo";
  calls print_usage on error or -h.

int main(int argc, char **argv);
- Main entry point:
  1. Initializes cli_config_t (parse_args)
  2. Applies configuration (set_staging_dir, set_staging_enabled, set_build_tmp_dir from system_helpers)
  3. Creates Pool (pool_create)
  4. Loads repository (load_repository from parser.c)
  5. Decides by command:
     - install/build: Creates solver, solves dependencies (solve_dependencies), creates transaction (solver_create_transaction),
       displays plan (display_transaction), user_confirm if not dry-run, iterates through transaction steps,
       downloads packages (download_package), downloads extras (download_extras), builds (commit_element from builder.c)
     - resolve: Only solves + displays transaction without download/build
     - repos: Shows repo name and package count (repo->nsolvables)
     - repo-update: Frees repo/pool, recreates pool, calls generate_repodata, reloads repository, shows package count
  6. Cleanup: repo_free, pool_free, free(cfg pointers)
  7. Returns exit_code (0=success, ERR_SOLVE_FAIL, ERR_DOWNLOAD_FAIL, ERR_BUILD_FAIL)

Supported commands
----
install <pkg>
- Full workflow: dependency resolution → download → build → install (install phase TODO)
- Usage: balikar install glibc

build <pkg>
- Alias for install (same behavior); semantically designated for build-from-source workflow
- Usage: balikar build hello

resolve <pkg>
- Dependency resolution only (dry-run solver); shows transaction plan without executing changes
- Usage: balikar resolve gcc

repos
- Shows loaded repositories and package count
- Usage: balikar repos

repo-update
- Regenerates repodata.json from current repository structure; frees pool/repo, calls generate_repodata,
  reloads repository and shows statistics
- Usage: balikar repo-update

download <pkg>
- Downloads package source files without building; supports --output-dir for custom target path
  or uses local repository from repos.conf; with --no-deps downloads only the package without dependencies
- Usage: balikar download bash
         balikar download --output-dir=/tmp/sources glibc
         balikar download --no-deps --output-dir=/custom/path gcc

Global options
----
-h, --help
- Shows help message (print_usage) and exits with exit_code 0

-d, --debug
- Increases debug_level (can be repeated: -d -d for level 2); applied globally through common.h logging

--dry-run
- Simulation mode: shows plan, skips download and build; useful for previewing changes

- Disables staging mode (set_staging_enabled(0)); installation proceeds directly without DESTDIR=$P intermediate step

--staging-dir=PATH
- Sets custom staging directory (default: $P from system_helpers); calls set_staging_dir(PATH)

--chroot-path=PATH
- Sets path to chroot environment (default: /tmp/pm-chroot); not yet used (TODO for installer)

--build-tmp-dir=PATH
- Sets temporary directory for builds (calls set_build_tmp_dir); default: /tmp

--repo=PATH
- Sets path to repository (default: ./repo); used in load_repository

--local-package=PATH
- Path to local tar.bz2 package outside repo (TODO: implement add_package_tar_bz2 workflow)

--output-dir=PATH
- Target directory for download command; downloads packages to specified directory
  in structure <letter>/<name>/<name>-<version>/; if not specified, uses first
  local repository from repos.conf

--no-deps
- For download command: downloads only the requested package without dependencies

Workflow install/build
----
1. Create Solver (create_solver from solver.c)
2. Dependency resolution (solve_dependencies from solver.c):
   - Finds main package, recursively adds mkdeps, creates job Queue, runs solver
3. Create Transaction (solver_create_transaction from libsolv):
   - Converts solver output to transaction with steps (INSTALL, UPDATE, etc.)
4. Display plan (display_transaction from builder.c):
   - Prints list of packages to install/build
5. User confirmation (user_confirm from cli_helpers.c):
   - If not --dry-run, asks user for confirmation
6. Order transactions (transaction_order):
   - Orders steps by dependencies (leaf-first for correct build order)
7. Iterate through steps:
   - For each INSTALL/MULTIINSTALL:
     a) Gets download_url (get_custom_source from parser.c)
     b) Downloads package (download_package from downloader.c) - returns FILE* with content
     c) Downloads extras (download_extras) - patches/scripts
     d) Builds (commit_element from builder.c) - extraction, patch application, .build execution
8. Cleanup (transaction_free, queue_free, solver_free)

Workflow resolve
----
- Same steps 1-4 as install/build, but skips steps 5-7 (no download/build)
- Useful for checking dependencies without system changes

Workflow repos
----
- Simple informational output: shows repo_path and repo->nsolvables (number of loaded packages)

Workflow repo-update
----
1. Free current repo and pool (repo_free, pool_free)
2. Create new pool (pool_create)
3. Call generate_repodata (from parser.c):
   - Traverses repo/ directory structure
   - Loads index.json, processes tar.bz2 archives
   - Computes SHA256 hashes, creates repodata.json
4. Reload repository (load_repository)
5. Show statistics (package count)

Error handling
----
- Each critical operation checks return values
- Error states: ERR_SOLVE_FAIL (dependency fail), ERR_DOWNLOAD_FAIL (download fail), ERR_BUILD_FAIL (build fail)
- Goto cleanup pattern for proper resource deallocation (repo, pool, malloc'd strings)
- If pool/repo creation fails, immediate return 1
- On transaction error: break from loop, set exit_code, goto cleanup

Workflow with --local-package
----
1. Extract archive to temporary build directory
2. Download .build script and extras from repository
3. Copy .build to source directory
4. Set DESTDIR and P environment variables
5. Execute .build script (or fallback to configure+make)
6. Install from staging to target root
7. Update package database
8. Cleanup temporary directories

Example: balikar install --local-package=/path/to/gzip-1.14.tar.xz --staging-dir=/tmp/staging --root=/mnt/lfs

Staging vs Root directories
----
--staging-dir: Temporary build destination (DESTDIR for make install)
  - Default: /tmp/balikar_staging
  - Cleaned after installation
  - Intermediate storage between build and install

--root: Final installation target (chroot environment)
  - Default: / (native system)
  - Permanent installation location
  - Database location: {root}/var/lib/balikar/installed.json
  
Process flow: BUILD → staging-dir → root
