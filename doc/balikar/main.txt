main
=============

Popis
----
Zdrojový soubor: src/balikar/main.c

Modul main je vstupním bodem aplikace. Po refaktoringu (Command
Pattern + Dispatcher, 2026-04-09) je úmyslně extrémně tenký – jen
4 kroky bez business logiky:

    1. command_context_create() – alokuje CommandContext (CLI config
       + lazy resources: Pool, Repo, subsystems function pointers)
    2. command_context_parse_args(ctx, argc, argv) – naplní context
       z CLI argumentů; rozpozná příkaz a jeho options
    3. command_dispatch(ctx) – najde v command_registry odpovídající
       handler a spustí ho (validate → execute)
    4. command_context_destroy(ctx) – uvolní context, vrátí exit kód

Cílem této struktury je:
    - Žádné business rozhodnutí v main – vše dělají moduly
      (command_context, command_registry, jednotlivé cmd_*.c)
    - Triviální testovatelnost: tests/main.c má identickou strukturu,
      jen s mockovaným command_registry
    - Snadné přidávání nových příkazů: stačí napsat nový cmd_xxx.c
      a zaregistrovat jej v command_registry.c – main.c se nemění


Klíčové funkce
----

int main(int argc, char **argv);
- Vstupní bod programu. Vrací:
    0   úspěch
    1   command_context_create selhal (out of memory)
    !=0 návratový kód command_dispatch (= návratový kód handleru
        konkrétního příkazu)


Chybové kódy
----
1                   command_context_create selhal
viz cmd_*.txt       Návratové kódy konkrétních příkazů jsou zděděny


Integrace v projektu
----
Na main.c jsou navázány:
    - command_context.c (vytvoření a destrukce kontextu, parsování CLI)
    - command_registry.c (mapování názvu příkazu → handler)
    - common.c (logging init, výchozí cesty)
    - Všechny cmd_*.c moduly (přes registr)

Build artefakty:
    CMake target "balikar"  → samotná binárka (src/balikar/*.c
                              + src/common/*.c + src/utils/*.c)
    CMake target "tests"    → testovací binárka, používá
                              tests/main.c místo src/balikar/main.c
